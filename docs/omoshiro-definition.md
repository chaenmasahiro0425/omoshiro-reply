# 「面白い」の定義 — リプライの場合

このリポジトリの全部の判断は、このページの定義から来ている。
プロンプトも採点表も、ここを書き換えたら追従させる。

## 1. 結論（一行）

> **面白いリプ ＝ 読み手の予想を外したのに、0.5秒で「わかる」に着地し、誰も本気で傷つかない一言。**

分解すると4つの掛け算になる。どれか1つでもゼロなら、全体がゼロになる。

```
面白さ ≒ 意外性 × 着地の速さ × 無害さ × 当事者性
```

| 要素 | 意味 | ゼロになる例 |
|---|---|---|
| 意外性 | 「次はこう言うだろう」の予想を外している | 「すごいですね！」「〇〇が大事ですね」 |
| 着地の速さ | 外した後、説明なしで一瞬で意味が通じる | 前提知識が要る・二度読まないと分からない |
| 無害さ | ずれ（違反）が安全な距離にある | 人格攻撃・弱い立場いじり・炎上ネタ |
| 当事者性 | その投稿のその細部に、その人が言うから効く | どの投稿にも貼れる汎用コメント |

## 2. 根拠（ユーモア研究で一番強い3つの説を、リプ向けに読み替えた）

### 2.1 不一致の解決（Incongruity-Resolution）
笑いは「予想と違う」（不一致）だけでは起きず、「あ、そういうことか」と**解決できた瞬間**に起きる。
意外なだけの文は「意味不明」、解決しかない文は「当たり前」。
→ 採点表の **意外性** と **着地の速さ** はこの2段に対応する。

### 2.2 2つの筋書きの重なり（Script Opposition / GTVH）
ジョークは、1つの文が**2つの対立する読み方**（筋書き）の両方に当てはまることで成立する
（Raskin の意味論的スクリプト理論、Attardo & Raskin の一般言語ユーモア理論）。
「お前じゃい！」が効くのは、「AIっぽいと指摘する人」と「指摘する本人がAIっぽい」が同時に立つから。
→ 生成では「この投稿を、別の筋書きで読むと何になるか」を必ず考えさせる。

### 2.3 安全な違反（Benign Violation）
McGraw & Warren（2010, Psychological Science）は、笑いを「**違反**でありながら同時に**無害**と判断される状態」と定義した。
無害に見せる方法は3つ。①別の規範では許される ②その規範へのこだわりが弱い ③心理的に距離がある。
違反がなければ退屈、無害でなければ不快。
→ リプでは「常識・空気・お約束」を軽く破る。人を殴らない。殴るなら上（大企業・自分・AI）を殴る。

## 3. なぜAIのリプはつまらないのか

usutaku さんの指摘（2026-11-08）が核心を突いている。

> AI生成のリプライがつまらないのは、AIに面白いリプを作る能力がないからではなく、
> 面白いリプライをしようと人生で一度も思ったことがない人達が、AIを動かしているからである

実際のリプ欄（2026-11-08 に自分の投稿5本で観察）を並べると、AIっぽいリプは同じ型をしている。

1. **投稿の要約を言い直す**（「〜という割り切りが印象的です」）
2. **無難に褒める**（「〜なのが強いですね」「〜が大事ですね」）
3. **取って付けた自分語り**（「私も〜を任せていて〜」）
4. **一般論で締める**（「任せる範囲を広げるほど〜」）

これは技術的にも説明がつく。

- 言語モデルは「一番ありそうな次の言葉」を選ぶ。**ありそう＝予想どおり＝意外性ゼロ**。笑いと真逆の方向に最適化されている
- 安全に寄せる調整で、違反（ずれ）を避ける。**違反ゼロ＝退屈**
- 同じ指示で何度作らせても似たものしか出ない。ChatGPT に冗談を1,008回言わせたら、9割以上が同じ25個の使い回しだった（Jentzsch & Kersting, WASSA 2023）
- そして最大の原因は、**選ぶ人がいない**こと。1案目をそのまま貼っている

逆に、人間で一番伸びていたリプは型が違った。

| リプ | なぜ効くか |
|---|---|
| 「お前じゃい！」 | 2つの筋書きの重なり（指摘する側が指摘される側）。4文字で着地 |
| 「AIのリプライに手動で返してしまった時の虚しさ半端ないです」 | 誰もが経験した場面の解像度。自虐で無害 |
| 「ヒューマノイドがこれだけいたらスターウォーズごっこできますね！」 | 見立て。投稿の細部（大量のロボ）に乗っている |

## 4. 仕組みへの落とし込み

「面白い人」は1発で面白いことを言っているのではなく、**頭の中で大量に出して、ほぼ全部捨てている**。
大喜利の芸人も、構成作家も、数を出して選ぶ。
ユーモア生成の研究でも、最近の上位手法は「幅広く出して、選ぶ」の2段で、**ボトルネックは選定側**だと報告されている（SemEval-2026 Task 1）。
さらに、LLMの審査員どうしは人間とより**お互いに**似た好みを持ち、並び順にも引っ張られる（Cards Against LLMs, 2026）。

そこでこのリポジトリは、面白い人の頭の中をそのまま工程にした。

| 工程 | 面白い人の頭の中 | 実装 |
|---|---|---|
| 1. 読む | 「みんな何て言いそう？」「どこにツッコめる？」 | **ベタ予測**（避ける領域）と**ツッコミどころ**を先に洗い出す |
| 2. 出す | 型を変えて何十個も思いつく | 12の笑いの型 × 複数案。ベタ予測に似た案は機械で落とす |
| 3. 捨てる | AI臭・説明くさい・長い・危ないを捨てる | ルールの減点（AI臭検知）＋安全チェック |
| 4. 選ぶ | 一番いいのを見極める | 別系統の審査員2人で採点 → 並び順を入れ替えた一騎打ち |
| 5. 削る | 言い回しを詰める | 作家役が削る。削った版が元より強いときだけ差し替える |
| 6. 本人が選ぶ | — | 最後は人が選ぶ。選んだ・捨てた記録を次回の審査の手本にする |

6番目が usutaku さんの指摘への答え。**AIに選ばせて終わりにしない。選ぶ人の好みを仕組みに溜める。**

## 5. 採点表

各10点。総合点は掛け算型（1つでも低いと全体が沈む）。

| 軸 | 10点 | 0点 |
|---|---|---|
| 意外性 | ベタ予測のどれとも違う角度 | ベタ予測とほぼ同じ |
| 着地 | 説明なしで一瞬で分かる | 二度読んでも分からない |
| 具体性 | この投稿のこの細部にしか効かない | どの投稿にも貼れる |
| 簡潔さ | 一息で読める（目安40字以内） | 長文・説明つき |
| キャラ | 言う人の口調と立場に合う | 言う人が言うと不自然 |
| 無害さ | 誰も本気で傷つかない | 攻撃・差別・炎上の火種 |

AI臭（定型句・絵文字の盛り・要約の言い直し）は別にルールで減点する。

## 6. やらないこと

- **投稿しない**。このツールが作るのは下書きまで。貼るかどうかは人が決める
- 弱い立場・個人の容姿や属性をいじらない
- 政治・宗教・災害・事件・病気をネタにしない
- 事実をでっち上げない（数字・発言の捏造）
- 他人のリプ欄を荒らす目的で大量に使わない
